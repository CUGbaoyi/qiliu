# 栖流设计与交互验证

本文记录栖流从初版到 0.4.0 的设计依据、对照检查、修正历史与残留限制，供后续界面改动参考。它是设计与 QA 的历史记录，不是部署或使用文档；当前界面以仓库代码与 [README](../README.md) 中的演示截图为准。

## 视觉依据与范围

- 初版视觉依据来自一张生成稿中的桌面 + 手机双栏参考图（原始参考图未入库）。
- **桌面参考区域**：(10, 42)–(1226, 970)，1216 × 928。保持纵横比缩放到 1320 × 1007，放入 1320 × 1024 对照画布，没有拉伸原图。
- **手机参考区域**：(1247, 43)–(1589, 970)，342 × 927。保持纵横比缩放为约 390 × 1057；原生成稿的手机区域实际比 390 × 844 更长，因此额外在 390 × 844 与 360 × 800 验证真实窄屏。
- **实现截图**：`docs/desktop-demo.png`（1320 × 1024）、`docs/mobile-demo.png`（390 × 1057），浏览器 CSS 视口与图片像素 1:1。
- **对照条件**：演示账号、总览、默认密度、无搜索无筛选、未收藏、无弹窗；真实数据状态另行检查。
- **完整对照图**：`docs/comparison-desktop.png`、`docs/comparison-mobile.png`，参考图与实现放在同一张图中检查；重点区域为 `docs/comparison-account.png`，检查账号数值、单位、标签、间隔与数据优先级。

## 修正历史

1. **P2：额外演示横幅将首屏资源下移。** 首次对照发现多出的横幅改变总览比例。删除总览额外横幅，将提示保留在账号状态中；桌面返回真实数据放到页头。重新截图后账号区与资源区的层次恢复。
2. **P2：手机字体和缩略图过小。** 增大手机用户名、数值、辅助标签、资源标题及缩略图，保持 360px 无横向溢出。最终数值完整显示，底部导航标签在视口内。
3. **P1：快速切换演示模式后，空收藏可能保留加载状态。** 清理 loading/syncing 状态并为收藏单独处理空列表。正式构建复测空收藏显示正确引导，不再显示持续加载。
4. **数据接入修正：RSS 描述为实体编码 HTML。** 修正标准 XML 实体解码，同时保留 DTD/自定义实体拒绝。新增编码 RSS 测试；真实订阅验证图片和纯文本，无原始 HTML 注入。

## 五项视觉检查（初版深色方案）

以下记录对应 0.2.0 之前的深色青绿方案；0.2.0 起主题改为白色 + 橙色，但排版、间距与内容优先级的结论仍然适用。

- **字体与排版**：系统中文无衬线字体、宋体品牌文字，主数值采用等宽数字；桌面标题 30px、主要数字 32px，手机 25px，窄屏按宽度缩小。长标题截断，详情可阅读全文。
- **间距与布局**：固定桌面侧栏、上方账号面板、下方资源表；手机流量双列、分享率单行、辅助统计 2×2、底部导航。390px 与 360px 的页面宽度等于视口，无水平滚动。
- **颜色**：深蓝灰页面、较亮表面、青绿主数值与选中态，演示/失败使用暖色提示；细分隔线，不堆叠仪表卡片。
- **图片与图标**：演示资源使用单独生成的山岳、海岸、极地、城市、森林照片；真实内容使用站点图片。Phosphor 标准图标，未以自绘 SVG/CSS 图画替代视觉资产。
- **内容**：上传/下载/分享率优先；缺失考核明确「暂不可用」。真实数据与演示数据明确区分。额外的同步时间和账号详情入口是功能完善所需，不改变核心层次。

## 残留限制

- 图标库中的站点符号替代了设计稿中示意 M 图标；真实 M-Team 名称保留。
- 演示图片按同一主题重新生成，非设计稿像素级裁切。真实资源封面由站点提供，可能无封面或加载失败，显示可识别的资源图标。
- 原生系统字体在 Android 与 macOS 的字形会有差异。
- 初版未在实体 Android 手机验证；跨网络访问和原生分发不属于当次交付。
- PWA 安装需 HTTPS 或 localhost，当前局域网 HTTP 主要用于浏览器访问。

初版没有未解决的 P0/P1/P2 视觉问题。后端测试和静态检查另见 [README](../README.md)。

## 0.2.0 更新验证

0.2.0 将主题改为白色与橙色，并要求独立的 Android、macOS 与 NAS Docker 形态。此要求覆盖旧深色设计，但保持账号优先的页面层级，新增独立的上传与魔力收益区域。

- 桌面 1320 × 1050 白橙截图、手机 390 × 844 与 360 × 800 截图均为本地实证，不入库。
- 手机 scrollWidth 等于视口宽度；新增收益卡片为 2 列，底部导航保持固定，内容可滚动。
- IPv6 输入 `http://[fd00::1234]:8080` 通过 URL 输入校验；下载器连接弹窗打开、输入、关闭正常。
- macOS WKWebView 原生应用实际启动，URL 为 `qiliu://app/index.html`；保存连接后可读取站点资源（本地验证），无需 localhost 服务。
- Android APK 使用 Android SDK 35 构建，最低 API 26（Android 8）；APK v2/v3 签名验证通过。未在实体手机安装，不能声称实机验证通过。
- Docker ARM 实际容器以 node 用户、只读根目录、移除 capabilities 运行且健康检查通过。登录、无凭据拒绝、收藏保存、重启持久化、旧会话失效和重新登录通过；浏览器 NAS 登录与站点管理通过。
- AMD64 镜像构建成功，并在本机 AMD64 运行环境中做模块启动检查；未在真实 NAS 部署。
- 当次自动化测试、lint 和前端构建通过，覆盖原生适配、收益映射、qBittorrent 会话失效重试、NAS 权限与 IPv6 连接回归。
- 每小时收益使用官方 `finalBs`，预计每日按 ×24 计算。未连接下载器时界面明确显示「连接后可用」，不伪造速度。
- macOS 应用为本地 Ad-hoc 签名，未做 Apple 公证；双架构已构建，实际 UI 运行验证为 Apple Silicon。本次未发布到公网。

## 0.4.0 设计变更

- 总览只保留「账号概览」与「上传与魔力收益」两块，不再显示最新资源列表，也不在总览发起资源请求；资源列表只出现在发现、订阅与收藏。
- 新增顶部站点切换器（M-Team / TJUPT），驱动总览、发现与刷流；订阅、收藏和下载任务与站点无关。
- 新增刷流助手：上传量 / 魔力值两种模式，展示评分构成与推荐理由，可按时间、下载人数、体积与「仅免费」筛选；只排序、不自动加种，发送复用现有下载弹窗。
- 新增「设置 → 备份与迁移」：口令输入与备份文本框都在页面内完成，不依赖 WebView 下载文件。
- 移动端底部导航收敛为 5 项：总览、刷流、发现、下载、我的；订阅入口移至「我的」。
- 修复 390px 移动端横向溢出（刷流筛选、站点切换、底部导航），并补充资源排序、相对时间展示与下载页只读说明。
- 账号错误与资源错误分开显示；资源列表请求失败时保留上次结果并标注「显示上次结果」。
- 0.4.0 的真实账号截图同样仅本地留存，不入库；仓库内截图均使用演示数据。
